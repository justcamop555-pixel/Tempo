## Tempo 1.0.316

**The clicker stops burning a CPU core, notification cards finally wear the sending app's own icon, macros can be checked and repaired, and every list in Tempo is readable and colour-coded.**

### The clicker barely touches the CPU now
Holding an accurate click interval meant busy-waiting the last 4 ms of every single one — accurate, but the cost grew as the interval shrank, and at high click rates it was enormous. Measured on this machine before the change: **67 CPS burned 23% of a CPU core, 200 CPS burned 66%, and 400 CPS pegged an entire core at 99.9%** doing nothing but spinning.

Tempo now sleeps the interval on a high-resolution kernel timer and spins only the last fraction of a millisecond.

| clicks/sec | CPU before | CPU after |
|---|---|---|
| 10 | 3.1% | **0.4%** |
| 67 | 22.8% | **0.0%** |
| 100 | 35.3% | **2.6%** |
| 200 | 65.6% | **0.5%** |
| 400 | **99.9%** | **0.8%** |

Accuracy improved at the same time — worst-case drift at 67 CPS fell from 7.5 ms to 0.2 ms. Windows 10 1803 and later get this automatically; older builds keep the previous behaviour, and Live debug says which is in use.

### Notification cards show the app that sent them
A Discord message arrived wearing **Tempo's** logo. Windows only offers the notification listener a logo for *packaged* Store apps — for ordinary desktop programs (Discord, Chrome, Steam, Telegram, most of what actually notifies you) it returns nothing, and every one of those cards fell back to Tempo's own icon.

Tempo now finds the icon the other way round: it locates the running program behind the notification and takes the icon off its executable, matching on the app's shell identity first and its name second. Verified end to end on Discord, Steam, Chrome, Edge and Medal; 68 of 68 identified apps resolved. A failed lookup is retried later rather than remembered forever, so an app that wasn't running yet still gets its icon once it starts.

### Check and repair a recorded macro
New **Fix…** button on the Macros tab. It inspects a recording and offers to repair what it finds:

- **Keys and buttons that are never released** — the worst recording fault there is: playback ends with the button still held, so the mouse sticks or the character keeps walking.
- **Clicks that land off-screen** — a macro recorded on a monitor layout you no longer have. Pulled back onto the nearest screen.
- **Duplicate moves and empty waits** — recording samples the pointer far faster than anything reacts to it.
- **Machine-perfect timing and aim** — identical gaps to the millisecond, or dozens of clicks on the exact same pixel. Optionally scattered so it doesn't read as a metronome.
- **Marathon pauses** — the thirty seconds you spent reading the screen mid-recording.

Problems are ticked by default, suggestions aren't, every repair is described before it runs, and the work happens on a copy so a failure can't leave a half-fixed recording. On a real 405-step macro it found that **148 of 202 gaps were exactly 16 ms** — the recorder's own sampling rate showing through.

### Every list is readable now — and colour-coded
A stock Windows list can only ever be half-themed: the rows follow the theme but the **column header is drawn by the system and ignores it**, which is why `#  Time  Action  Detail` was near-black text on a near-black strip in every list in the app.

All four lists — **Live Monitor, Recent sessions, Multi-Point and the macro step editor** — are now drawn by Tempo: readable headers, subtle row striping, and a colour per row that means something.

- **Live Monitor and the step editor** colour by action: blue for movement, green for left click, orange for right, violet for middle, amber for keystrokes, cyan for scroll, grey for waits. A long recording can be read at a glance instead of as four columns of identical text.
- **Recent sessions** colours by profile, so sessions group visually.
- **Multi-Point** colours by mouse button, matching the same palette, and dims a point that's switched off.

The colours are fixed hues rather than tints of your accent, so left-click is the same green on every theme — but each one is lightened or darkened per theme until it clears a 4.5:1 contrast ratio against the row behind it. Checked across **all 38 themes: 874 contrast measurements, all passing**, light themes included.

### Fixes

- **The window came back broken after picking a coordinate.** Using the pick-position hotkey hid the window, and restoring it never rebuilt the page's backdrop — with a background image every control is transparent, so the window returned as a hole with the desktop showing through and only a few controls visible. Fixed, along with the same fault in Multi-Point's Quick Capture and in restoring from the tray.
- **Pick-position is ignored while Tempo is in the tray.** It used to take over the whole screen and write the coordinate into a window you couldn't see.
- **The clicks-by-button bar stamped a grey slab over your background image.** It now sits on the image, its legend can't overlap itself or run off the edge, the coloured segments no longer square off the bar's rounded ends, and an empty bar says so instead of looking broken.
- **Switching tabs did the work twice.** Every switch ran a follow-up pass that repainted the whole page again whether or not anything had changed — measured at 36–92 ms of pure duplicate work per switch. It now only repaints when it actually corrects something, which across every switch sampled was never.
- **A wrongly-reported "your window is broken" warning** and a **stats panel that scrolled back to the top twice a second**, making anything below the fold unreadable in Live debug.
- **Untranslated text is now visible.** A missing phrase silently fell back to English, so it could ship unnoticed for months — running Spanish immediately surfaced **177** genuinely untranslated phrases, including the whole Notifications section. Live debug now reports the count and names offenders. (Those translations are catalogued, not yet written.)
- **Animated backgrounds are capped at 30 repaints a second.** A GIF with 10 ms frame delays was asking for 100 full-window repaints per second.

### Known issues
- **Escape still doesn't leave full screen — use F11.** Both keys travel the same path and F11 arrives; Escape never does, and it isn't a hotkey conflict. Still being chased.
- **Switching *to* the Clicker tab takes ~100 ms.** That page carries by far the most controls and painting them is the entire cost — it is not the background image (measured: it's the same or slightly slower with the image turned off). Reducing it means changing how those controls draw, which hasn't been done yet.
