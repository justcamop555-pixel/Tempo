## Tempo 1.0.218

**THE portable-exe fix: the build script was overriding it. Tempo.exe now truly runs from any folder, on its own.**
- Found the real cause of "only works inside its folder": the publish script (publish.cmd) was passing build flags that turned OFF native-library bundling and single-file packing - overriding the project setting. Command-line flags win over the project, so 1.0.217's fix was being cancelled at build time.
- The publish script now bundles EVERYTHING into Tempo.exe: the .NET runtime, the UI Automation assemblies, and the native speech-engine libraries (whisper / ggml / NAudio). The result is one self-contained Tempo.exe you can move or copy to any folder - desktop, USB stick, another PC - and it runs with no DLLs beside it.
- IMPORTANT: this is a build-script change. You must rebuild with publish.cmd (which runs dotnet publish) to get the portable exe. A plain Visual Studio Build, or copying the exe out of bin\Release, will still leave loose DLLs - that's how .NET works, not a Tempo bug. The single file only comes from publishing.
- The settings live in your AppData (the AutoClicker folder), so the portable exe keeps its settings wherever it runs.

Windows may show "Unknown publisher" because the app isn't code-signed - click More info → Run anyway. It's safe.
