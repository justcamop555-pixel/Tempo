## Tempo 1.0.314

**A notification overhaul: one card per event however many tabs are open, the app's real icon and name, and a click that opens the app that sent it. Plus a title bar that matches your theme and a loading screen that reports real progress.**

### The sidebar shows its keyboard shortcuts
Tempo has always let you jump straight to a tab with **Ctrl+1…9**, and cycle with **Ctrl+Tab** — but nothing in the app ever said so, so nobody found them. Each sidebar row now carries its number, dimmed at the right edge: visible when you look for it, quiet when you're not. Hovering a row names the shortcut in full ("Open the Macros tab · Ctrl+3. Ctrl+Tab cycles through the tabs."), and each row now reports itself to screen readers as a tab with its shortcut instead of an unlabelled button.
### The version stamp no longer doubles up
Resizing the window could leave the sidebar showing **two** "Tempo v…" stamps, each with its own separator line. The sidebar owner-paints that footer anchored to its bottom edge, but the panel wasn't marked to repaint on resize — so Windows invalidated only the newly exposed strip, the footer was redrawn at the new bottom, and the old one survived as stale pixels. The panel now repaints in full on resize (it's 188 px wide, so the cost is nothing). Verified by cycling the window through 700 → 900 → 760 → 1000 → 824 px: one line, one stamp, no ghosts.
### The version stamp (and status bar) can't fall off the bottom any more
If the window ended up **taller than the usable screen**, its bottom edge sat under the taskbar — and the first things to vanish were the status bar and the sidebar's **Tempo v…** version stamp. Full screen matches the screen exactly, so everything fitted there, which is why the version only appeared in full screen. Tempo already clamped this when restoring a saved window; it now also clamps after you finish **resizing** the window and when a **display change** shrinks the desktop under it (a full-screen game exiting, a resolution switch). Measured: a 1020×1102 window on a 1834×1032 work area is pulled back to 1020×1032, and the version stamp reappears.
### The title bar matches the theme now
Tempo's window sat under a plain **black** system title bar. "Dark mode" was the best it could do, and a dark bar still doesn't match a *coloured* theme — on Synthwave it read as a black strip bolted above a purple app. On Windows 11 the title bar can be painted directly, so Tempo now colours it (and the window border) in the active theme: measured on Synthwave, the bar went from `#202020` to `#261C3A` against the header's `#251B39` — visually one continuous surface. It follows live when you change theme or when "Match Windows" flips light/dark, and it's applied to **every** Tempo window — the main window, Live debug, About, CPS test, overlay settings, the updater, calibration and the rest — so no dialog stands out. Windows 10 keeps the dark/light bar it always had.
### One card per notification, however many tabs are open
A web site open in **ten browser tabs** posts one logical notification — but each tab raises its own Windows toast, so the mirror faithfully produced **ten identical cards at once** and buried the screen. Windows gives each of those toasts a different id, so the existing id-based check couldn't see they were the same; only the content can. Tempo now collapses a repeat of the same app + title + body arriving within a few seconds into a single card, while still letting a genuinely repeated message through later (a second "You have a new message" a minute on is real news). This works for any source, not just browsers — any app that fires the same toast in a burst now gets one card. Verified with ten identical notifications fired back-to-back: **1 shown, 9 collapsed**, reported in Live debug as "9 duplicate(s) collapsed".
### Drawing on a snip no longer spams notifications
Annotating a screenshot in Snipping Tool fired **one "Screenshot copied to clipboard" card per brush stroke**, burying the screen. Snipping Tool re-copies the image to the clipboard on every edit, and Tempo's duplicate check keyed on the file SIZE — which changes with each stroke, so every stroke looked like a brand-new screenshot. It now keys on the picture's **dimensions**, which an edit doesn't change, and the window extends on each repeat so a long drawing session stays folded into the one card the shot already earned. Verified with eight simulated strokes: **0 extra cards**, and Live debug reports "12 re-copy/edit(s) folded in".
### A screenshot always opens in the app that took it
Clicking a screenshot card could still open **Photos** instead of Snipping Tool. Tempo learned which app took the shot from that app's *notification* — so if you clicked the card before the notification arrived (it appears within ~160 ms, the notification can take longer), or if that app's notifications were turned off, Tempo had no source and fell back to whatever program owns `.png`.

Tempo now asks Windows **who put the image on the clipboard** the instant it appears — the clipboard owner is the capture tool itself — and reads its app identity straight from the process. No notification needed, so there's no race to lose and it works with that app's notifications switched off. The app's own notification, if one arrives, only refines the label. Executable names are tidied for display too (`SnippingTool.exe` → "Snipping Tool"). Verified by snipping and clicking the card **immediately**: opens Snipping Tool, logged as "clipboard image came from SnippingTool.exe (Microsoft.ScreenSketch…)".
### The card catches up with the Windows toast
Mirrored cards trailed Windows' own toast on mid-range PCs. The cause was the source app's icon being decoded **on the critical path** — several blocking WinRT round-trips plus an image decode, repeated for every single notification. Icons are now decoded once per app and reused (a copy is handed to each card, so nothing is shared unsafely), which takes that cost out of the path entirely. With the decode gone the poll interval was also tightened from 120 ms to 70 ms, which is only worth doing now that the decode isn't dominating.
### A cleaner card
- **The ✕ moved to the left**, inset from the rounded corner. It used to sit hard against the top-right — cramped, and exactly where the pointer travels when you click the card body to open the app, so a mis-click dismissed the notification instead of opening it. Left-hand placement separates "dismiss" from "open".
- **New setting: "Show ✕ on cards"** (*Settings → Notifications*). Turn it off for a cleaner card — it still dismisses on a click and still auto-closes, so nothing becomes unreachable, and the app icon and name slide left to fill the space.
- **Roomier layout** — more padding so the text isn't tight to the edges, and more air between the title and the description.
- **Restyled countdown bar** — slimmer, rounded, with a faint full-width track behind it so it reads as time remaining rather than a divider under the card.
### Notification timing, reworked
- **Long messages stay long enough to read.** "Show (s)" is now the **minimum**, not the whole story — a card earns extra time from how much text it carries (~200 wpm, the pace Windows uses), capped at 3× your setting or 20 s. A one-line "Screenshot copied" still goes in 5 s; a five-line mirrored chat message no longer vanishes mid-sentence.
- **Cards appear faster.** The brief hold that lets a screenshot card merge with the capture app's notification is halved (320 → 160 ms) — and it no longer costs you the app's identity: the card now shows **immediately** and is **re-labelled in place** the instant the capture app's notification arrives. You get "Snipping Tool" with its icon *and* an instant card, instead of trading one for the other.
- **Snappier motion.** The slide-in converges in ~3 frames instead of ~5, and the slide-out and stack reflow are correspondingly quicker — the card feels like it's already there rather than travelling.
- **Staggered stacks.** When several notifications land together their timers are nudged apart, so the stack drains one card at a time instead of the whole group blinking out at once.
### Quick switches in the tray menu
Right-clicking Tempo's tray icon now toggles the things you'd otherwise have to open the window for: **Live captions** on/off (previously only the hotkey could do it, so a user whose hotkey was taken by another app was stuck), **Pop-up notifications**, and **Screenshot alerts** — plus a **Settings…** item that opens the window straight on the Settings tab. Every toggle shows its real state when the menu opens and saves immediately, and screenshot alerts grey out when notifications are off, since they ride on the same system.

### "I installed it but some features don't work" — now diagnosable
Tempo ships as one self-contained `Tempo.exe`: the .NET runtime **and** the offline speech libraries are packed inside, and the single-file host unpacks the native ones to a temp folder at start-up. That normally just works — but on some machines it silently doesn't (antivirus or an enterprise policy blocking `%TEMP%`, a "temp cleaner" deleting the folder, `%TEMP%` full or redirected). When it fails, Tempo still opens and clicking still works, so the install *looks* healthy while Live Captions can never start — with nothing anywhere explaining why.

Tempo now checks its own bundle at start-up and says what it found: an **Install** line in Live debug ("single-file bundle OK · natives staged in …"), a line in the log, and — if the speech libraries genuinely didn't load — a **Health error naming the cause and the exact folder involved**, so it can be allow-listed instead of guessed at.

### No more "Settings saved." dialog
Saving settings popped a modal that had to be clicked away to confirm something you had just done deliberately — an interruption at exactly the moment you were carrying on. The **Save Settings** button now confirms in place: it reads **"Saved ✓"** for a moment and returns to normal by itself. Same reassurance, nothing to dismiss. **Save Keybinds** does the same. Genuine warnings still get a real dialog — saving keybinds with a duplicate combination, for instance, is worth interrupting for.

### A window that's Tempo all the way to the edge
The system title bar is gone. Tempo's own header **is** the title bar now, drawing its own ─ □ ✕ in your theme — with the maximise glyph swapping to a restore glyph, and close turning Windows-11 red on hover. Windows won't let an app restyle its caption buttons, so the only way to theme them is to own the whole bar.

Everything a title bar has to *do* still works, because Tempo tells Windows where its zones are rather than reimplementing any of it: **dragging, Aero Snap, double-click-to-maximise and edge/corner resizing** are all still native. Maximise is clamped to the monitor's work area so it never covers the taskbar, and full screen (F11) hides the buttons and brings them back on exit.

### Check for updates and view the source from the tray
Two more entries on the tray menu: **Check for updates…** runs the same check as the Settings button without opening the window, and **View source on GitHub** opens the repository directly — Tempo is open source and that shouldn't be buried inside the About dialog.

### Sidebar shortcut numbers sit clear of the labels
The Ctrl+1…9 hints were drawn with a different text engine to the labels — one that adds its own padding around the glyph, letting a digit drift toward the label or the rounded edge. Both now use the same renderer with explicit spacing: a fixed gap from the border and a wide gap before the label, so a long name like "Multi-Point" can never crowd its number.
