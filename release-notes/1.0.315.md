## Tempo 1.0.315

**Tempo's real logo everywhere it should have been all along, and a window that behaves like a Windows 11 window again — the taskbar button minimises it, and minimise, restore and close are properly animated.**

### The header shows Tempo's actual logo
The header drew a hand-made lightning-bolt glyph on a coloured tile. It was a placeholder, and it never once touched Tempo's real artwork — so the logo in the header didn't match the icon in the taskbar, the tray, or on notification cards, and the custom logo you can set in **About** never appeared there at all.

The header now draws the real thing: your custom logo if you've set one, otherwise Tempo's own icon, with the drawn bolt kept only as a fallback if neither can be loaded. The artwork **replaces** the coloured tile rather than sitting inside it — dropped into a bright accent square, a full-bleed logo reads as a murky blob in a coloured ring. It gets the rounded tile to itself with a hairline accent rim, the way every other app draws its icon. Set or clear a logo in About and the header updates immediately instead of waiting for a restart.

### Sharper logos on notification cards
The `Icon` class doesn't hand back the size you ask it for. `ToBitmap()` rasterises at the icon's own 32 px whatever the caller wants, and asking for a 256 px frame returns the 128 px one even though the file genuinely contains a 256. Both end in a smaller frame being blown up, which is exactly the soft, mushy logo Tempo was showing. Tempo now decodes the frame it actually wants straight out of the icon: measured at a requested 256 px, the old route produced 128×128, the new one a true 256×256 with real detail rather than interpolation.

### The taskbar button minimises the window again
Clicking Tempo's taskbar button while Tempo was in front did **nothing**. Going borderless for the custom title bar makes Windows drop four window style bits, and one of them is the bit the taskbar reads to decide whether it may minimise a window. Tempo puts those bits back and removes the frame they would otherwise draw, so Windows treats it as an ordinary window while Tempo still paints every pixel itself. Clicking the taskbar button now minimises, and **Win+D**, **Win+Down** and *Show desktop* work on it too.

### Windows 11 animations for minimise, restore and close
The same missing style bits meant the desktop compositor ran none of its transitions on Tempo — it blinked in and out of existence while every other Windows 11 app glided. Those animations are back. Measured by capturing frames during a minimise: **zero** intermediate frames before, **105** after, the window scaling smoothly down to the taskbar.

Closing to the tray is animated too. It used to vanish instantly, which reads as a crash rather than "it's still running, in the tray". It now plays the real shrink-to-taskbar animation and hides once that finishes — and reopens the way it went in, maximised if it was maximised.

### Maximise no longer runs off the edges of the screen
A maximised window sat 8 px past every edge of the screen, pushing the top of the header and the whole status bar out of view. The resize frame Windows adds to a maximised window was being counted as usable space. The client area is now pulled back to exactly the work area — measured 1834×1032 against a 1834×1032 work area, with the taskbar still visible and nothing clipped.

### Live debug reports the window and the logo
Two failures in this release were completely silent — a taskbar button that quietly refuses to minimise, and a logo that falls back without saying so. Both are now reported:

- **Window styles** — the live style word, whether the window is minimisable and framed, and a loud warning if either is missing (`taskbar click-to-minimise and window animations are DEAD`).
- **Logo** — whether the header is drawing your custom logo, Tempo's icon (and the size it decoded at), or the fallback bolt.

### A false "your window is broken" warning is gone
Live debug reported **"Full-screen state is inconsistent — press F11 twice to resync the window"** on a perfectly healthy window. The check treated "borderless" as "must be full screen", which stopped being true when Tempo started drawing its own title bar and became borderless permanently. Health now reads clean.

### Known issue
**Escape still doesn't leave full screen — use F11.** The banner offers both; only F11 works. Investigated at length for this release without a confirmed cause: F11 and Escape take the same path through the window's key handling, F11 arrives and Escape never does, and it isn't a hotkey conflict — Tempo binds no Escape hotkey. Still being chased.
