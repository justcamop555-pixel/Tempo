## Tempo 1.0.293

**Why "Try GPU engine" seemed to do nothing · captions can no longer fall seconds behind in silence**

### Ticking "Try GPU engine" while Tempo was running did nothing — silently

The speech engine's CPU/GPU choice is fixed the moment the first model loads, and it
**cannot change until Tempo restarts**. So if captions had already run once in that
session, ticking the box simply didn't apply. No message, no hint. You'd sit watching
the CPU engine lag and wonder why the graphics card wasn't helping.

Now Tempo **says so outright and offers to restart on the spot**. And Live Debug shows
a loud warning whenever your GPU setting and the engine actually running disagree:

```
⚠ GPU setting is ON but this run locked in the CPU engine — RESTART TEMPO for it to take effect.
```

### The same trap applied to auto-downgraded models

When a model can't keep up, Tempo drops to a smaller one **for the session** — and your
real choice only returns on restart. Live Debug now says that explicitly, instead of
leaving you to wonder why you're stuck on `medium`.

### Captions can no longer sit permanently seconds behind

The audio backlog was allowed to grow to **8.4 seconds**.

An engine that can't quite keep up would fill that buffer and then just *sit* at the
cap — still transcribing every word, but every word landing on screen many seconds
after it was said. Forever, and invisibly. That is exactly the "it works, but it lags"
state.

The backlog is now capped at about **3 seconds**: audio older than that is dropped so
that what's on screen tracks what's being said **now**. Live captions are worth more
current than complete — and the too-slow ladder still shrinks the model, so a machine
that genuinely can't cope gets fixed rather than hidden.

### Falling behind is no longer silent

Dropping audio to catch up now logs a plain warning — "the engine is behind live audio
… a smaller model, or the GPU engine, would keep up" — instead of happening with no
trace at all.

Windows may show "Unknown publisher" because the app isn't code-signed — click More info → Run anyway. It's safe.
