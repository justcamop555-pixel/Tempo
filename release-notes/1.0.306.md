## Tempo 1.0.306

**The CPU engine finally gets the whole CPU · Tempo's F11 glitch fixed · honest about games nothing can draw over**

### The CPU engine can keep up now
Watched live on a 10-core machine: the Large model on the CPU engine produced
20-second chunk times and the auto-ladder collapsed it to Base within minutes.
Root cause: a hard-coded **6-thread cap** was starving every big model. Four
fixes, together:

1. **All the cores.** The engine now counts PHYSICAL cores properly and uses
   all of them minus one (9 of 10 on the machine above; hyperthreads don't help
   whisper's math). During a fullscreen game it takes HALF the cores instead —
   the CPU engine is now as courteous to games as the GPU path. Live debug's
   Decode line shows the thread count.
2. **Warm-up inference.** The first chunk of every session was paying the
   model page-in cost on live audio — every session opened with a backlog
   spike and a "dropped n s" line. Tempo now runs 1.5 s of silence through the
   engine during "Loading speech model…". Measured live: warm-up 1.2 s, and the
   session-opening 5.6 s drop was gone.
3. **Marginal engines stretch instead of bleeding.** An engine at ~1.0–1.4×
   real time transcribes everything yet sheds a few hundred ms every few
   seconds, forever. The counter-intuitive fix: BIGGER steps — the encoder's
   cost per chunk is flat, so 1.5× windows mean ~30% less work per second of
   speech. Engages by measurement, shows as "stretched ×1.5" in Live debug,
   drops out when headroom returns.
4. **Downgrades recover.** The too-slow ladder only ever went DOWN — one busy
   stretch and you sat on Base all session. Tempo now steps back UP toward
   your chosen model after minutes of sustained headroom (never mid-game), one
   rung at a time — and if the bigger model immediately fails again, it stays
   stepped down instead of bouncing. The Health panel tells you which state
   you're in.

### Tempo's own full-screen window (F11) can't glitch anymore
Reported with screenshots: after full-screening Tempo itself, pages could show
cards duplicated/overlapping or missing, and the window could come back with no
title bar and a stray bottom scrollbar. Two real defects compounded:

1. The page re-centring routine froze painting while moving controls — and an
   exception mid-move skipped the un-freeze, so the page never painted again:
   stale pixels of the old layout mixed with the moved controls.
2. One silent exception in the F11 exit could abandon the whole window restore:
   no title bar, no minimum size (hence the scrollbar state), half-restored
   layout.

Both are fixed at the root (the un-freeze now always runs; every step of the
F11 restore is independent and logged), and Tempo also **self-heals**: a window
found border-less outside full-screen mode is detected and repaired. Entering
F11 now runs the same repair-and-repaint pass as a window restore — pages come
up complete, centred, and fully scrollable.

### Captions and REAL fullscreen — the honest answer
Tested live: the caption bar doesn't appear over a game running in old-style
**Exclusive Fullscreen**. That's a Windows-level wall, not a Tempo bug — a game
in that mode owns the whole display and *no* app can draw over it. (Discord and
Steam manage it by injecting code into the game itself — an anti-cheat gamble
Tempo will never take.)

What Tempo does about it now:

- **It detects the state** (through the shell's own "a game owns the display"
  signal) and tells you once, plainly: switch the game's video setting to
  **Borderless / Windowed Fullscreen** — it looks identical, performs the same
  on Windows 10/11, and captions appear over it.
- **The Health panel and log show it** ("EXCLUSIVE fullscreen — caption bar
  cannot be shown") instead of leaving you to wonder.
- **Over normal fullscreen you get visual proof**: the moment game mode starts,
  the bar briefly shows "🎮 Game mode — captions keep running at a lighter
  pace", so you can see the overlay working over Borderless games immediately.

Windows may show "Unknown publisher" because the app isn't code-signed — click More info → Run anyway. It's safe.
