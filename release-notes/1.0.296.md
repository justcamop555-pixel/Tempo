## Tempo 1.0.296

**Burst mode ignored the safety cap · more hotkeys are now bindable · tested live on real hardware**

### Burst mode was blowing straight through Anti-Freeze

With the Max-CPS cap set to 10, Interval mode correctly held 10 CPS — but Burst mode hit
**256 CPS** (measured live, peak 294) while the panel still cheerfully read "Protected".

Burst mode never called the anti-freeze path at all, so the safety cap **and** the CPU
back-off did nothing — in the one mode fast enough to actually lock a machine up.

Fixed and verified: the same test now holds ~10 CPS, and a legitimately fast rate
(cap 2000) still runs full speed. A subtler hole — burst size 1 with a 0 ms pause,
which slipped past through the between-bursts gap — is closed too.

### The two CPS numbers no longer contradict each other

With a Double/Triple/Quadruple click type, the Clicker tab showed **two different rates
for the same setting**: "Click Interval" counted real clicks (e.g. 114 CPS), "Manual
Speed" counted presses (29 CPS), and nothing said why.

Both now spell it out — `34.5/s × 4 = 137.9 clicks/s` — so the numbers agree and the
multiplier is visible.

### More hotkey combinations can be bound

Windows Forms was silently swallowing a whole class of key combos before Tempo ever saw
them, so **Ctrl+Delete, Ctrl+A, Ctrl+V, Shift+Delete** and the other editing shortcuts
simply could not be assigned as hotkeys. They all bind now.

(Tab, Enter, Space and the arrow keys — added last release — keep working.)

### See whether a hotkey is actually reaching Tempo

On the Keybinds tab, a binding's row now **flashes green the instant its key is
pressed**, from any application. "Is my hotkey even getting through?" is now answerable
at a glance, instead of by trying the action and watching for a side effect.

### Tempo warns when Windows refused a hotkey

If another program already owns a combination, Windows won't reserve it, and Tempo
quietly falls back to catching it with a keyboard hook. The action still fires — but the
key **also** keeps doing its normal job in the other app. That "my hotkey half works"
state was completely invisible before; the Keybinds tab now says it outright so you can
choose a cleaner combination.

### Faster multi-point clicking

The engine was allocating a fresh list on every single click in multi-point mode —
hundreds of short-lived objects a second on its hottest path. Now reused, so there's
less for the garbage collector to trip over during a fast run.

---

Much of this release was found and verified by driving the real app on real hardware,
not only by reading the code.

Windows may show "Unknown publisher" because the app isn't code-signed — click More info → Run anyway. It's safe.
