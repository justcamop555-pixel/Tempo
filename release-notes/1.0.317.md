## Tempo 1.0.317

**Your background image now covers the whole window, the window comes back intact after minimising, and the title-bar buttons keep focus.**

### The background image finally reaches the page

Your wallpaper showed on the header, the sidebar and the footer band — but the main content area stayed a flat grey slab, so the image looked like it was framing a hole rather than filling the window.

Measured on the Clicker tab, sampling one pixel from each surface:

| Surface | Colour |
|---|---|
| Header | RGB(90, 47, 58) — image |
| Sidebar | RGB(83, 35, 43) — image |
| Footer band | RGB(56, 39, 51) — image |
| **Page** | **RGB(40, 42, 54) — the bare theme colour, no image** |

The page had full backdrop support the whole time; it just never got switched on. Two things lined up. The backdrop is applied while the window is still being built, at which point the tab control has no handle yet and reports *no* selected tab — so no page was matched. And the code that would have switched it on later lives in the tab-changed handler, which is subscribed *after* the starting tab is set, and never fires at all when the remembered tab is the first one.

The result was that the page you landed on never lit up. Switching tabs once fixed it for the rest of the session, which is why it looked so arbitrary.

Now the starting page is resolved by index when the selected tab isn't available yet, and the wallpaper is switched on explicitly once the opening tab is chosen. Verified on a cold start with no tab switching, and on all six tabs: every one reads RGB(84, 35, 44) against the sidebar's RGB(83, 35, 43) — the page slice and the sidebar slice are continuous, which is the point. One image, one animator, every region on the same frame.

### The window no longer comes back damaged after minimising

Restoring Tempo could bring back a window with its header stripped of the logo, profile caption and the ─ □ ✕ buttons — and in the worst case a black void over the lower two-thirds with the desktop icons behind Tempo showing *through* the sidebar.

The restore repair only ever repainted the tab control and its pages. The header, sidebar, footer band and status strip were left holding whatever Windows had in the buffer when the window went down. Those surfaces draw the shared backdrop themselves, so a restore has to drop the cached backdrop and redraw the whole window, parent then child — not just the page that happens to be selected.

Verified by capturing the window straight off the screen and counting unpainted pixels: **0.0% across five consecutive minimise/restore cycles**, and clean through a maximised round trip too.

### Title-bar buttons hold focus

Windows refuses to bring an app forward when another program owns the foreground, so minimise/maximise/restore could act on a window that then sat behind whatever was in front. The caption buttons now take the foreground properly when they act.

### Also in this release

- The maximise/restore glyph stays correct through every route into and out of maximised.

### Known issues

- Escape still doesn't leave full screen; **F11 does**.
- Switching *to* the Clicker tab still costs about 100 ms — its own controls, not the background image.
