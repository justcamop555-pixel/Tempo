## Tempo 1.0.313

**Scrolling is about 8× faster. Tempo reopens on the tab you were using. Two full-screen bugs that permanently wrecked your window size are fixed. And "Match Windows" now matches your accent colour too.**
### Scrolling is ~8× faster
Scrolling any tab used to crawl — measured at **11 FPS** (90 ms per scroll step) on a 16-core machine, and worse on tall pages like Settings and Keybinds. The cause: Tempo set the `WS_EX_COMPOSITED` window style permanently, which makes Windows re-composite the **entire** window — header, sidebar, every card, checkbox and combo, footer — into one off-screen buffer on *every* repaint. That cost tracks the number of controls and the repainted area, not whether a background image exists, so it was being paid constantly.

That compositing is only actually needed while a **wallpaper** is showing (the mode where page labels and checkboxes turn transparent over the pinned backdrop, which is what caused the hollow-checkbox and clipped-label artifacts). Tempo now switches it on only in that mode. With no wallpaper — the default — the same scroll now measures **95 FPS (10.5 ms per step), an 8.6× speed-up**, with no artifacts: Windows' normal scroll blit is already pixel-perfect when the controls are solid. Set a background image and the compositing (and its smoothness) comes straight back automatically.

### Window, tabs & full screen
- **Tempo reopens on the tab you were using.** It used to always open on Clicker, which quietly lost your place in the case that matters most: a long unattended run where Windows reboots overnight and launch-at-startup brings Tempo back — you'd return to the Clicker page instead of the Macros tab you left it on. New tick box under *Startup & Window*: **"Reopen on the tab I used last"** (on by default; untick it to always start on Clicker). The tab is remembered even through a reboot or force-quit, and writing it is debounced so clicking through tabs costs nothing.
- **Full screen no longer wrecks your window size.** Two real bugs are fixed:
  - Pressing **F11 from a maximised window** overwrote Windows' restore rectangle, so the next "Restore Down" handed back a window the size of the whole screen at the top-left — its bottom edge (the status strip and the Macros **Live Monitor** card) buried under the taskbar, with your real window size gone for good.
  - **Exiting Tempo while in full screen** saved the full-screen rectangle as your remembered *normal* window size (borderless full screen is technically a "normal" window), so **every later launch** opened screen-sized at 0,0 with the bottom clipped — permanently, until you resized by hand. Tempo now stores the size the window had *before* F11, and a settings file already spoiled by this heals itself: the restored window is clamped to the monitor's working area so it can never sit under the taskbar.
- **Layout repair fix.** A page could be marked "already laid out" by a pass that actually turned back early, leaving cards where a half-finished pass had put them until something forced a full re-layout.

### Themes & "Match Windows"
- **"Match Windows" now matches the accent too.** With the **Light** or **Dark** theme selected, Tempo follows Windows' light/dark mode *and* adopts your Windows accent colour — so the buttons, highlights and header pick up the exact colour you set in Windows Settings → Personalization → Colors, not a fixed built-in accent. It updates **live** the moment you change either in Windows.
- **Colourful themes keep their look.** Pick Synthwave, Ocean, Dracula, and the rest, and "Match Windows" leaves that palette (and its designed accent) untouched instead of quietly forcing plain Light/Dark. A **custom accent colour** still overrides everything.

### Notifications — a big silent bug, and one card per screenshot
- **Notifications were switched OFF whenever Tempo started in the tray.** This is the important one. With **"Start minimised to tray"** on — the normal setup, and every launch-at-sign-in — Tempo's window is never shown at startup, and the code that arms the Windows-notification mirror and the clipboard screenshot watcher only ran when the window was first *shown*. So on a tray start, mirroring and screenshot alerts were **completely dead until you happened to open the main window**. Tempo's own log made it obvious once we looked: the mirror kept starting several minutes after launch — at exactly the moment the window was first opened — and on a launch where it was never opened, it never started at all. Both are now armed the moment Tempo loads, tray start or not.
- **One card per screenshot, not two.** Taking a screenshot fires two separate things: the clipboard changes (instantly) and the capture app posts its own Windows notification a moment later — so you got Tempo's card *and* a mirrored "Snipping Tool" card, side by side, for one action. They're now **merged into a single card** that wears the capture app's real name and icon, shows the shot itself, and tells you what clicking will do.
- **Clicking a screenshot card opens it in the app that took it** — Snipping Tool, not whatever program happens to own `.png` (Photos). Snipping Tool declines direct file activation, so Tempo uses the file association that app registered, looked up live at runtime — nothing is hard-coded, so it works the same for other capture tools. If the app genuinely can't take the file, it still falls back to your default viewer.
- **The same picture doesn't alert twice.** Apps re-publish an image to the clipboard as a side effect — Snipping Tool does it when loading a shot into its editor, which made clicking "open in Snipping Tool" immediately pop a second, identical card. Each picture now alerts once.
- **Live Debug** gained a **Screenshot alert** line that reports whether the clipboard watcher is genuinely *registered*, not merely ticked in settings — the exact mismatch that hid the bug above.

### Live Debug — now covers the window, rendering, tabs and theme
Every bug fixed above lived in a part of Tempo that Live Debug said **nothing** about, so each one had to be found by hand — a clipped card noticed by eye, scroll frames counted by feel. New lines close that blind spot:

- **Window:** state, size, position, client size, DPI, and the monitor's work area — with a loud **⚠ BIGGER THAN THE WORK AREA — bottom is under the taskbar** when the window is oversized (exactly the damage a full-screen exit used to leave). Plus the full-screen flag, the border style, and the saved restore rectangle, flagged if the flag and the border ever disagree.
- **Rendering:** whether a wallpaper is showing and whether whole-window compositing is on — reading **"fast scrolling"** normally, and **⚠ composited with NO wallpaper — scrolling will crawl** if the slow path ever comes back.
- **Tab:** the current tab, whether "reopen on last tab" is on, and which tab is remembered.
- **Theme:** the active theme, Match Windows on/off, whether Windows is light or dark, and the accent **with its hex and where it came from** — the theme, your custom colour, or Windows. A "my colours look wrong" report now answers itself.

The health section also flags these fault conditions up top, so they're spotted rather than merely displayed.
